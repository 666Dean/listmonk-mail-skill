# Windows 本地启动与诊断

listmonk.exe 是服务进程，界面在浏览器；直接双击可能因配置或数据库缺失退出。运行目录应包含 config.toml。用终端在实际程序目录执行并读报错；不要输出完整 config.toml，因为含数据库密码。

若部署已有 start-listmonk.cmd / stop-listmonk.cmd，优先复用并检查其路径，不硬编码某台机器的用户名或安装目录。浏览器地址通常为 http://127.0.0.1:9000，仍应以实际配置为准。

排查顺序：

1. 检查 exe 架构、运行目录和配置文件存在性。
2. 查日志尾部并遮蔽秘密及个人信息。缺配置时，仅在没有现有配置的目录用 `--new-config` 生成，不覆盖用户配置。
3. 检查 PostgreSQL 进程与监听端口，再验证数据库连接。数据库默认 5432，便携部署可能用其他端口。
4. 检查网页监听端口是否已占用，确认占用者属于该实例；不杀无关进程。
5. 首次安装到明确的新空数据库才运行 `--install`；不要用它修复已有库。修改数据、升级前按请求范围备份，保留已有名单与账号。
6. 验证 HTTP 响应和管理员页面；没有 SMTP 配置时只汇报服务可访问，不汇报邮件已能发送。

本机环回部署可以连接外部 SMTP 发信，但外部收件人无法访问其图片、退订、浏览器版本、跟踪链接或像素。不要把 127.0.0.1 / localhost 的链接放进正式邮件。准备订阅营销邮件时需要公网 HTTPS 部署，或外部可访问的退订/媒体方案，不能用禁用退订代替部署。

关闭浏览器不会停止后台服务。发送/定时期间电脑必须开机并保持服务运行。不要未经用户请求设置开机自启或开放防火墙。
